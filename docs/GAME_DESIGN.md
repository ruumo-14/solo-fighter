# SOLO FIGHTER — 確定ゲーム設計・反映台帳

この文書は、過去の設計会話と2026-11-23の80問回答をまとめた実装基準。未確定の数値・未接続機能を、完成済みと扱わない。

## 1. 作品の方向性
- 完全オリジナルの世界観。簡単なストーリー。
- 大規模な本格ゲーム。アップデートで継続的に拡張する。
- 基本はソロプレイ。イベント等で友人と交流・協力・競争する。
- 戦闘・収集・育成・攻略・競争をすべて高水準にする。
- ステージ制の横視点アクション。戦闘の操作技術が大きく影響する。
- 既存システムは基本的に変更しない。新規拡張は既存仕様との整合を取る。

## 2. ステージ・戦闘
- 1ステージ最大7分（420秒）。2分・4分・6分にボスが出現し、最後のボスを倒すとクリア。7分までに倒せなければ失敗。
- 前ステージをクリアすると次ステージ解放。マップ形式で選択。クリア済みは何度でも再挑戦可能。
- ステージ背景は固定。地形は平坦。環境ギミック・特殊ルール・隠し要素は設けない。
- 再挑戦時のステージ構成は毎回同じ。評価ランクは設けず、クリア/失敗を記録。
- ステージの舞台は自然・遺跡・洞窟・人工施設など多彩にする。
- 敵は多数の種類と個性的な行動。敵個体差は設けず、強化個体を用意。通常出現と大集団出現を組み合わせ、一部の敵は連携する。
- 既知の敵行動：獣は追随・接触攻撃。ゴブリンは接近後に予告して突進。スケルトンは点滅予告後に放物線の矢を撃つ。飛行敵「ホバリン」は接近・停止後に突進し、突進中に攻撃を受けると元の位置へ戻る。
- ボスは複数の攻撃パターン。一部ボスのみ形態変化・専用報酬。登場演出は簡潔。ボス再戦可能。
- 攻撃演出は爽快感重視。撃破演出は通常表示。コンボシステムなし。重要な場面のみカメラ演出。
- 一部のランダムイベントを追加するが、ステージ環境ギミックやステージ特殊ルールにはしない。
- モードはノーマル以外に、ボスラッシュ・サバイバル・エンドレス等の複数ルール。無限挑戦、高難易度専用の敵・ボス・報酬を用意。高難易度は段階的に難しくなる。

## 3. キャラクター・ペット
- キャラクター入手はガチャ中心。全キャラクターに専用演出。キャラ個別ストーリーはなし。
- 同じキャラクターでもレアリティ違いがあり、高レアほど基礎能力が高い。ノーマルは特殊能力なしで基礎能力のみ。
- キャラクターの基本能力は低めにし、レベルアップの成長を感じられるようにする。
- ペットは能力差で個性を表現。見た目バリエーションは少なめ。ペット図鑑・展示・キャラとの相性システムなし。
- ペット最大Lv.20。ペットの自然回復は全員固定。スキルで回復を早められる。
- キャラ/ペットの基本的な図鑑は作らない（キャラ情報は基本情報のみ）。
- キャラの専用攻撃アニメーションを作る。剣の場合は剣・魔法・二刀など躍動感のある動きを含める。

## 4. 育成・スキル・装備
- 育成要素はレベル・装備・スキル。育成の振り直し可能。
- プレイヤー最大Lv.100（以降の上限解放はアップデートで段階追加する別企画の設定と混同しない。SOLO FIGHTERでの上限はこの設計値）。
- 装備はガチャ中心で入手。部位は頭・胴・脚・足・手・武器の6つ。
- 装備に防御力は設定しない。装備セット効果あり。装備強化は専用素材を使い、最大Lv.10。強化は難しめ。
- 装備の見た目変更機能はなし。
- スキルの組み合わせは非常に自由。スキル組み合わせによる追加特殊効果はなし。
- スキルのレアリティはノーマル/レア/エピック/レジェンド/S1。通常スキルはノーマル中心。ノーマルが大量に出すぎないようにし、他レアリティの確率を少しだけ上げる調整希望。
- スキル提示数など、過去に未回答の項目は推測で確定しない。

## 5. ガチャ・レアリティ
- レアリティ：ノーマル / レア / エピック / レジェンド / S1。
- 通常ガチャ：アイテム等50%、ノーマル10%、レア35%、エピック4%、レジェンド1%。
- S1ガチャ：アイテム等50%、ノーマル10%、レア33%、エピック4%、レジェンド2%、S1 1%。
- 100連天井カウンターは独立管理する設計。天井時に何を保証するか、バナーごとの厳密な対象は未確認のため、未確定のままにする。
- レアアイテムの獲得演出は通常表示。ドロップ履歴・アイテム図鑑・収集率報酬はなし。

## 6. 報酬・経済・取引
- ゲーム内通貨は「魔晶」。用途は幅広くする。
- ステージ報酬は経験値・魔晶中心。
- アイテム一覧はシンプル。売却は通常売却。
- 取引所・個人ショップなどプレイヤー間売買機能を導入する。
- イベント限定アイテムを用意する。
- 取引・ガチャ・ランキング等のオンライン経済処理はサーバー側で検証する。ブラウザだけで通貨や抽選結果を確定させない。

## 7. 友人向けオンライン・イベント
- 友だち登録システムはなし。
- 自由チャットを導入。
- 公開プロフィールはクリア記録のみ（プロフィール表示は名前・レベル・戦力・称号）。
- 友だち限定ランキングはなし。総合ランキング＋週間ランキング。
- 定期イベント。イベントは専用ステージ・特殊ルール・限定ボスを含む。
- グループ協力型の大型イベント、複数ルールの大会を開催。
- 報酬は限定キャラ・装備・称号など。

## 8. 実績・日課・プロフィール
- 大量の実績と珍しい称号。
- プロフィール表示：名前・レベル・戦力・称号。
- ログインボーナス、デイリー/週間ミッション。
- チュートリアルは最低限。
- エリアごとにBGMを変更。
- UIはシンプルで見やすく。

## 9. 80問回答のうち、明確に「なし」としたもの
- 敵個体差、環境ギミック、ステージ特殊ルール、隠し要素、評価ランク、コンボ、キャラ個別ストーリー、ペット図鑑、ペット展示、キャラとペットの相性、装備外見変更、アイテム図鑑、収集率報酬、レアドロップ履歴、友だち登録、友だち限定ランキング。
- ただし、イベント専用ステージの特殊ルールはイベント設計として別途あり。

## 10. 実装状況の扱い
- 仕様が設計文書に書かれていることと、ゲーム内で動作することは別。
- オフラインで実装できるシステムと、Supabase等のサーバー設定・認証・Realtime・Edge Functionが必要な機能を分ける。
- オンラインアカウント、クロスデバイス保存、チャット、取引、ランキング、協力イベントはサーバー設定と安全なサーバー処理が必要。
- 未実装の機能を完成扱いにしない。各機能にテストを追加する。
